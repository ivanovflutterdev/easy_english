# Easy English

Flutter-приложение для изучения английских слов. Интерфейс на русском: полупрозрачные панели, светлая/тёмная/системная тема, адаптивная навигация.

## Запуск

```sh
flutter pub get
flutter run
```

Flutter 3.41.1 / Dart 3.11. Без Firebase приложение запускается в локальном режиме.

## Что реализовано

- Карточки с раскрытием перевода, примером и четырьмя оценками воспоминания.
- SM-2-подобные интервалы; ошибка возвращает слово через минуту.
- Локальное сохранение каждого ответа, ежедневные цели, XP, серии и постоянные достижения.
- Каталог Oxford, поиск, британская/американская TTS-озвучка и регулировка скорости.
- Настройка темы, акцентного цвета, размера текста и прозрачности.
- Ежедневные локальные уведомления с выбором времени и часовым поясом устройства.
- Android-виджет ежедневной цели. Исходник iOS WidgetKit находится в `ios/EasyEnglishWidget`; extension ещё нужно подключить в Xcode.
- Адаптеры Firebase Auth (вход, регистрация, восстановление пароля), Firestore (потоковая синхронизация ответов), FCM.
- Cloud Functions для рейтинга и ежедневных push о повторении; серверные правила Firestore.

## Словарь

Источник: https://www.oxfordlearnersdictionaries.com/wordlists/oxford3000-5000

`assets/oxford_catalog.json` содержит 4957 уникальных написаний из официального каталога: 2981 в базовом наборе и 1976 дополнительных. Это не число отдельных значений и частей речи: одно написание объединяется в одну карточку. Названия Oxford 3000/5000 относятся к исходным спискам, а не к числу уникальных записей после объединения.

Исходная страница содержит слова, части речи и уровни, но не русские переводы. В `assets/words.json` подготовлены 32 учебных примера с переводами; остальные слова видны в словаре, озвучиваются и включаются в занятия после сохранения собственного перевода. Переводы пользователя пока сохраняются только на текущем устройстве. Не выдаём отсутствующие переводы за полноценный готовый курс на 5000 карточек.

Каталог и учебные карточки входят в приложение и доступны офлайн. Для офлайн-озвучки установите английский системный голос. Аудиофайлы и определения Oxford не копируются; озвучивание выполняет TTS. Примеры и переводы стартового урока созданы для этого проекта. Перед публичным распространением сторонних учебных данных проверьте условия их использования у правообладателя.

Повторный импорт официального каталога:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tool/import_oxford.ps1
```

## Архитектура

- `lib/domain`: сущности, планировщик повторений, интерфейсы репозитория и сервисов; без Flutter/Firebase.
- `lib/application`: контроллер состояния и сценарии обучения; зависимости на интерфейсы domain.
- `lib/application/cubits.dart`: Cubit-проекции для учебной сессии, настроек и авторизации. UI можно переводить на точечные `BlocBuilder` без пересборки всего приложения.
- `lib/data`: локальный репозиторий, Firebase, TTS, уведомления, виджеты, настройки.
- `lib/presentation`: экраны и визуальные компоненты.
- `lib/main.dart`: композиция зависимостей и инициализация.

Ответы хранятся как неизменяемые события с уникальными ID. Повторы отправки идемпотентны; события с разных устройств объединяются и переигрываются в порядке времени. Локальные записи сериализуются, чтобы облачный снимок не затёр ответ. Гостевые данные изолированы от каждого аккаунта. Общие настройки интерфейса остаются на устройстве.

Состояние мигрируется на `flutter_bloc`: `LearningCubit`, `SettingsCubit` и `AuthCubit` уже подключены через `MultiBlocProvider`. Текущие экраны сохраняют совместимость с существующим контроллером; следующий этап — заменить широкие `ListenableBuilder` на точечные `BlocSelector` по экрану.

Текущее локальное хранилище использует SharedPreferences; для большого коммерческого курса стоит перенести журнал ответов в транзакционную базу SQLite/Drift. Публичный рейтинг начисляется сервером, но пока не имеет защиты от искусственного создания ответов; это функциональная основа, не античит-система.

## Подключение Firebase

Firebase-проект пока не создан. Код облачных интеграций подготовлен, но удалённые сервисы не развёрнуты и не проверены на реальном проекте.

1. Создайте Firebase-проект и приложения Android/iOS. Текущий Android applicationId: `com.example.easy_english`; перед выпуском задайте собственный идентификатор.
2. Установите Firebase CLI и FlutterFire CLI, выполните `firebase login` и `flutterfire configure`.
3. Включите Authentication → Email/Password и создайте Firestore. Примените `firestore.rules`; не включайте открытый test mode для публикации.
4. Убедитесь, что Android использует `google-services.json` и Gradle-плагин Google Services, а `GoogleService-Info.plist` включён в iOS Runner. Точка входа использует нативную конфигурацию через `Firebase.initializeApp()`; для других платформ передайте сгенерированный `DefaultFirebaseOptions.currentPlatform`.
5. В `functions` выполните `npm install` (Node 22), затем `firebase deploy --only firestore:rules,functions --project YOUR_PROJECT_ID`. Для расписания Cloud Functions потребуется соответствующий тариф Firebase.
6. На iOS включите Push Notifications и Background Modes / Remote notifications, загрузите APNs-ключ в Firebase. Проверяйте push на реальном устройстве.
7. В настройках приложения войдите в аккаунт и включите push. Push отправляется сервером в 16:00 UTC при наличии просроченных карточек; настраиваемое ежедневное напоминание работает отдельно, локально.

Cloud Function для push пока рассчитана на небольшой проект: обходит пользователей и историю ответов. Перед масштабированием нужны индекс просроченных повторений, региональные расписания, очередь отправки с повторами и мониторинг. Для конфликтующих офлайн-сессий сервер сейчас использует последнее сохранённое расписание карточки, а приложение пересчитывает все события.

## iOS-виджет и проверка платформ

На Mac откройте Runner в Xcode, создайте Widget Extension с именем `EasyEnglishWidget`, добавьте в него `ios/EasyEnglishWidget/EasyEnglishWidget.swift`. Минимальная версия этого исходника — iOS 17. Добавьте App Group `group.com.example.easyEnglish` в Runner и extension; при смене идентификатора измените его также в `ProgressWidgetService`. Настройте signing и embedding extension. Эти действия нельзя проверить на Windows; extension ещё не включён в Xcode project.

Стеклянный интерфейс реализован средствами Flutter (blur, прозрачность, границы); это не нативный API Apple Liquid Glass.

## Проверка

```sh
flutter analyze
flutter test
flutter build apk --debug
```

Тесты покрывают интервалы, сброс после ошибки, серии занятий, сериализацию, сохранение ответа, мобильную и широкую разметку с увеличенным текстом.

Не коммитьте сервисные аккаунты, signing keys, `.env` и локальные Firebase-конфигурации. Для release задайте собственную подпись Android; текущая конфигурация подписывает сборку debug-ключом.
